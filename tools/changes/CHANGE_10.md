# CHANGE_10：實機回饋修正、首頁日曆改版、鍵盤收合與點擊提示統一

前提：CHANGE_09 已完成並推上 GitHub。
這次一樣一次做完，CHANGE_07 的執行規則 1–7 繼續適用。完成後產出 tools/CHANGE_10_REPORT.md，並同步更新 SPEC.md 和 tools/STATUS.md。每一節各自 commit。

## 0. 實機測試發現的問題

### 0-1 歷程的統計頁捲不上去
現象：在統計頁捲到最底後，手指從「訓練頻率」卡或「平衡」卡開始往上滑沒有反應，要從「有氧」卡以上開始滑才捲得動。

先找出原因，寫進報告。我的推測有兩個：
- 訓練頻率圖的拖曳手勢吃掉了上下滑。
- 隱藏的分頁列還在攔截點擊。

修正的要求：
- 所有圖表（有氧、訓練頻率、體重、主項迷你折線、動作詳情的折線圖）都改成：點一下選取，按住約 0.2 秒後才能拖曳選取。一般的上下滑一律交給捲動。
- 隱藏狀態的分頁列不能攔截任何點擊。
- 如果可以建立 UI 測試：從訓練頻率圖的位置往上滑，確認捲動位置有改變。做不到的話，記在「未解決」，留給我實機確認。

### 0-2 分頁列的收起行為統一
現象：歷程捲到底部時分頁列會收起，動作庫卻不會。

規則：
- 四個分頁底下所有可以捲動的畫面，都在往下捲時收起分頁列、往上捲時出現，包括動作庫第 1 層、分類清單、歷程的紀錄和統計。sheet 和浮窗不套用。
- 全部使用同一個共用的 modifier。CHANGE_08 的規則照舊：離底部 80 pt 以內或回彈中不切換，同方向連續捲動 24 pt 才切換，分頁列的切換不能改變版面配置。
- 查出動作庫原本為什麼沒有收起，寫進報告。
- 「訓練中」橫條在分頁列收起時照樣顯示。

### 0-3 捨棄訓練
- 拿掉訓練畫面上方的 ••• 選單。如果選單裡除了「捨棄訓練」還有其他項目，先停下來，在報告裡列出來，不要直接刪掉。
- 在訓練畫面的最底部，也就是最後一個動作的下方，加一個紅字按鈕「捨棄訓練」。
- 按下後用置中的對話框確認：
  - 標題：「捨棄這次訓練？」
  - 內文：「這次訓練的所有組都會刪除，無法復原。」
  - 按鈕：「取消」和「捨棄訓練」（destructive）。
- 全 App 的確認對話框一律改成置中的 alert，不再用會變成 popover、帶箭頭的 confirmationDialog。範圍包括刪除訓練、覆蓋體重、結束目前訓練等所有確認。

### 0-4 動態島展開時，右上角的訓練時間被裁切
- 訓練時間一定要完整顯示，包括超過 1 小時的「1:05:30」。
- 數字用等寬字，限制一行。空間不夠時先自動縮小；還是放不下，就移到下一行（belowIfTooWide 或同等做法）。
- 同時檢查 compact 和 minimal 兩種狀態有沒有裁切。

### 0-5 DE 主項沒有顯示建議重量
現象：臥推（速度）只顯示「用能做得很快的重量」，沒有建議重量。

先在報告裡說明目前的計算方式。我推測是用「最近一次 ME 紀錄」計算，而角色系統是 CHANGE_06 才加的，臥推還沒有任何 ME 紀錄。

改成：
- 建議重量 = 該動作強度換算表的 1RM 基準 × 60%。直接共用強度換算表的計算函式和進位規則，不要另外寫一套。如果使用者在詳情頁切換的基準有存下來，就跟著用那個基準。
- 說明列顯示「建議 32.5 kg（60%）」，並把這個重量灰字預填在每一組的 kg 欄。
- 完全沒有可計算的紀錄時，才顯示「用能做得很快的重量」。
- ME 紀錄只用在主項進步卡。

### 0-6 「上一次」欄顯示「—」
- 查出臥推的「上一次」為什麼是空的，寫進報告。
- 取值規則：同一個動作、這次訓練開始之前最近的一次紀錄（沿用 CHANGE_07 A-4）。優先找同一個角色的紀錄；同角色沒有紀錄時，改用任何角色的最近一次，並在後面加上小字的角色名稱，例如「40×3・ME」。

### 0-7 訓練畫面的標籤
訓練畫面的動作標題旁只顯示這次的角色（例如「DE 主項」），不顯示動作庫的主、單、爆標籤。

## 1. 鍵盤收合
拿掉 CHANGE_08 加在鍵盤上方的「完成」按鈕，範圍包括：記錄體重、完成畫面的今天體重、強度換算表手動輸入 1RM、編輯動作、編輯說明。

改成以下三種收合方式：
- 可以捲動的畫面：往下捲動時收起鍵盤（scrollDismissesKeyboard(.interactively) 或同等做法）。
- 所有畫面：點輸入框以外的空白處收起鍵盤。記錄體重這類不能捲動的 sheet 一定要做到。
- 按下儲存、完成這類主要按鈕時，先收起鍵盤再執行動作。

其他規則：
- 訓練名稱欄位按 return 收起鍵盤的行為保留。
- 多行輸入（編輯說明）的 return 維持換行。
- 檢查全 App 其他的數字輸入，包括訓練中填重量和次數，確認拿掉之後都還收得起來。

## 2. 首頁訓練日曆
拿掉：
- 每週欄位上方的達標小點，以及圖例裡的「達標」。
- 標題列右側的「本週 N/目標・連續 N 週達標」，整段拿掉。
- 點一下或按住拖曳格子時浮出的小標籤，以及拖曳時的震動。

保留：
- 依部位上色和圖例：下肢、上肢、全身、有氧與其他。
- 每週目標的設定，以及歷程訓練頻率圖上的目標線。

刪除：
- 連續達標週數不再顯示在任何地方。刪掉只為它存在的程式碼和測試；達標判斷如果還有其他地方用到，就保留。

新增：
- 整張日曆卡都是點擊範圍，點一下打開「訓練狀態」浮窗（第 3 節）。
- 格子本身不再有個別的點擊行為。

## 3. 訓練狀態浮窗
半高 sheet，可以往上拉成全高，標題是「訓練狀態」。內容分成兩區。

### 3-1 本週
三行：
- 「本週・N 天（目標 M）・N 組」
- 「下肢 N・上肢 N・其他 N 組・有氧 N 分鐘」
- 「上週同期：N 天・N 組」

計算口徑：
- 本週從週一到今天。上週同期是上週一到上週的同一個星期幾（含當天）。
- 天數直接呼叫每週目標使用的同一個函式。
- 組數只算已結束訓練中打勾完成的正式組和 MAX 組，熱身組不算，和首頁近 30 天的組數同一套口徑，要共用同一個函式。
- 下肢＝下肢推＋下肢拉；上肢＝四個上肢分類；其他＝核心＋補強。
- 有氧不算組數，改算本週跑步機的分鐘數。

### 3-2 輪替狀態
依輪替順序列出四列：ME 下肢、ME 上肢、DE 下肢、DE 上肢。

每一列包含：
- 日型名稱。
- 上次：「N 天前（10/15）」；沒有紀錄時顯示「還沒練過」。
- 主項：「上次 深蹲 → 下次 傳統硬舉」；沒有紀錄時只顯示「下次 深蹲」。

標記與互動：
- 「下一次」卡目前推薦的那個日型，在該列加上「下一次」標記，顏色用 accent。
- 上次距今超過 14 天時，天數改用 warning 色。
- 點有紀錄的一列：打開該日型最近一次訓練的摘要浮窗，和歷程用同一個元件。
- 沒有紀錄的列不能點。

計算口徑：
- 「上次」只算該日型、有完成組的已結束訓練。
- 「下次主項」和「下一次」標記，必須直接呼叫建立菜單和「下一次」卡使用的同一個函式，不能另外寫一套。

## 4. 點擊提示統一
規則：能點的卡片和列，整塊都能點，按下時有回饋；全 App 不再用「›」當提示。

- 拿掉列和卡片右側的「›」，包括首頁的「下一次」卡和近 30 天長條、動作庫的分類列和「已封存」、設定第 1 層、歷程統計的主項進步，以及其他所有列尾箭頭。
- 不在這次範圍內：返回按鈕、訓練畫面的收合按鈕、訓練中橫條的展開箭頭、月份或週期的切換箭頭。這些是有動作的按鈕，維持原樣。
- 可以點的卡片和列（包括第 2 節的日曆卡、第 3 節可以點的輪替列），整個範圍都能點，並統一加上按壓回饋：按下時背景換成主題的按壓色（主題 token 沒有的話就新增），放開恢復。用同一個共用的 ButtonStyle 實作。
- 不能點的卡片（例如有氧、平衡）不要有按壓回饋。
